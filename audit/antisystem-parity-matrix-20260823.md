## Runtime baseline

The current project uses `@crysnovax/baileys` version **2.7.12**. The installed package exposes the default socket factory, cache-manager auth state, multi-file auth state, latest-version fetch, and cacheable signal key-store APIs.

## Highest-risk gaps to address first

1. **False logout/purge risk:** Mini’s local `classifyDisconnect` marks 403, 405, 440, and 500 terminal, while V1 preserves auth for recoverable/ambiguous cases. This can violate the specification’s purge-safety rule.
2. **Socket event-loop pressure:** Mini performs media resolution and other awaited work in `messages.upsert`; V1 has explicit inbound admission and fairness.
3. **No hysteresis in local heartbeat:** one failed passive probe immediately degrades and closes the socket.
4. **Weak lock observability/fencing:** Redis locks have TTL and token release but no owner/fencing/audit surface.
5. **Panel/control classification drift:** local and worker lifecycles do not share one authoritative error/recovery model.
6. **Missing complete health metrics:** queue depth, pending operations, event-loop lag, memory, retries, HTTP and Redis metrics are not unified per session.

## Safe implementation boundary

The first implementation slice should be non-destructive: centralize error classification, add session-scoped health/pressure metrics, add inbound admission around heavy event work, and add lock diagnostics/fencing tests. It must not purge existing sessions, stop healthy sockets, alter outbound WhatsApp traffic, or restart the panel supervisor. Any change affecting reconnect or worker release must be deployed with a backup and control-only restart, followed by read-only health verification.
